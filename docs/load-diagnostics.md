# Page loading and diagnostics

Open `/admin/?diagnostics=1` under the installation URL and sign in. The setting travels with admin navigation links. A Load diagnostics disclosure shows the slowest phases and lets you download a JSON timing report. Open a normal admin URL to turn it off.

Reports include navigation time, PHP Server Timing, API call durations, plugin imports and registration, rendering, and same origin resource timings. They contain timing values and sanitized paths only. Request bodies, response data, passwords, tokens, URL queries, fragments, external map URLs and order identifiers are excluded. Measurements stay in memory in the current tab until explicitly downloaded. There is no telemetry service or persistent diagnostic log.

PHP validates the session before loading initial page data. It returns current settings, active plugins, realtime configuration and the data needed for that admin page. Orders rows, report totals and catalog, driver and plugin previews render in PHP. Settings includes the bundled plugin forms. JavaScript enhances the initial content and handles updates, refreshing and saving. Initial data is consumed once per page and never stored in browser storage. Changing report filters fetches a fresh report rather than reusing a mismatched snapshot.

Navigation renders immediately after authentication. Skeletons cover interactive controls during initialization and respect reduced motion. Authenticated HTML and JSON remain uncached. Static assets can be revalidated. Module preload graphs fetch dependencies together; plugin imports overlap while registration and hook ordering remain deterministic.

Run `python3 scripts/build-preloads.py` after changing JavaScript imports or bundled plugin versions. The release builder also runs it. Commit `public_html/platform/preloads.json` with the release.

Initial live baseline on October 23: Orders ready in 1.61 seconds, of which plugin startup took 906 ms; Settings plugin startup took 830 ms. Direct server profiling measured a median 1.7 ms for bootstrap and plugin discovery. Browser timings depend on network conditions and are diagnostic samples, not a performance guarantee.

After the backend startup update, the same live browser measured Orders ready in 378 ms and Settings in 320 ms. Plugin startup fell to 19 ms and 12 ms respectively. Initial same origin request counts fell from 44 to 32 for Orders and from 50 to 34 for Settings. These are matched page samples from this session, not percentile statistics. The `Initial data` measurements read the authenticated PHP response; only `API` measurements represent subsequent transport calls. Report filter changes were verified to make fresh requests.

Customer tracking and the driver console use the same PHP startup pattern. Driver sign in is a PHP form protected by CSRF and the shared login limiter. The resulting HttpOnly session cookie lets PHP authorize and render assigned deliveries before scripts load. The browser receives its existing bearer session for subsequent updates and GPS. No customer contact details are saved in browser storage.

Private tracking links still arrive with credentials in the fragment. A small local script POSTs those credentials to PHP, which validates the order token and sets an HttpOnly cookie scoped to the tracking directory and that order. A 303 redirect opens `tracking/?order=ORDER_REFERENCE`. The token is never in a request URL or referrer. Refreshes render the current authorized order directly in PHP. Different order tabs have separate cookies; another browser needs the original private link. Expired or revoked access returns no order data. Keep `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on these pages.

Both pages include initial settings, plugin manifest, realtime configuration and public map configuration. Driver pages include scoped deliveries and GPS test configuration; customer pages include only their authorized public tracking response. JavaScript consumes these snapshots once, then uses HTTPS polling or WebSockets for updates. Driver actions and customer payment controls retain their existing API authorization. Map skeletons stay visible until the SDK succeeds or falls back, independently of control readiness. Reduced motion suppresses the pulse animation.

Add `?diagnostics=1` to driver sign in, or to the tracking URL before its fragment. The timing panel measures both pages without storing credentials or order details. Local browser verification measured driver controls ready in 100 ms and customer tracking in 40 ms, with initial data supplied by PHP. These local samples exclude Google network startup and are not live performance guarantees. Delivery start, automatic customer completion, map fallback and driver sign out were exercised using an isolated fictional order.

Diagnostics also include optional first contentful paint and largest contentful paint timings, a separate Google Maps initialization measurement, and diagnostics for the storefront and sign in forms. No external URLs, keys, locations or resource bodies are recorded. The storefront now embeds its public catalog and startup configuration through PHP. The reusable ordering component accepts a `catalog-data` attribute naming a public catalog meta element; standalone embeds retain their configured API fallback. PHP and JavaScript use the same public catalog snapshot, avoiding duplicate startup reads and preserving normal refreshes and authoritative server checkout validation.

Native PHP `Provides` and `Requires` attributes determine each page's browser plugin manifest. Only selected plugins are preloaded, styled and registered. Admin editor modules also load per page. Shared CSS imports are preloaded alongside the document, and selected plugin CSS is linked by PHP instead of waiting for JavaScript registration. The manifest and module graph remain separate from runtime secrets and merchant records. See `plugins.md` for the declaration contract.

See [the complete October 23 timing review](performance-2026-10-23.md) for matched before and after samples across all main pages, map readiness, sign in checks and remaining measurement limits. Generated preload graphs now also discover nested plugin stylesheets, so tables do not wait for an extra CSS request chain.
